# 战斗十人贡献图表与维度下钻设计

**状态：** 用户已确认交互方向，等待文档复核
**范围：** 战斗团战页面的“十人贡献与责任审计”
**目标版本：** Dota Lens 0.5.0

## 1. 问题

当前“十人贡献与责任审计”使用八列数字表格展示玩家、职责、伤害、技能、控制、治疗、在场率和评分。它存在以下问题：

- 十名玩家之间的差异需要逐行读数，无法快速比较。
- 天辉与夜魇同位置玩家没有对齐，位置职责差异不直观。
- 总分没有拆解，用户无法理解分数来自哪些事实。
- “证据不足”“客观条件阻断”“未参与战斗”和“确有责任问题”容易被混在一起。
- 点击玩家后虽然能看到原始指标，但不能从指标继续下钻到评分贡献、门禁和关联事件。
- 当前战斗和全场累计没有独立查看方式。
- Parser 只为有效参与者生成 `contributions`，当前界面不能稳定展示完整十人。

这不是单纯的样式调整。图表必须使用一致的计算口径，并且不能把没有通过职责硬门禁的数据画成确定评分。

## 2. 已确认的产品决定

1. 默认展示当前选中的战斗。
2. 标题右侧提供“当前团战 / 全场累计”分段切换。
3. 当前战斗始终展示全部十名玩家。
4. 未进入有效参与名单的玩家保留头像和位置，整行置灰。
5. 主视图使用天辉与夜魇镜像条形图。
6. 单个玩家使用位置职责雷达图和评分分项进行下钻。
7. 点击图表中的玩家或维度，在现有右侧责任审计面板显示详细数据。
8. 不使用十人叠加雷达图。
9. 饼图只适合单项可加总占比，不作为职责评分主视图。

## 3. 方案比较

### 3.1 双饼图

分别展示天辉和夜魇在伤害、治疗等单项指标中的玩家占比。

**优点：** 单项构成直观。
**缺点：** 职责评分、在场率和到场延迟不能相加；零值与未参与玩家不可见；多个饼图会占用大量空间。
**结论：** 不作为主视图。

### 3.2 十人热力矩阵

以玩家为行、维度为列，通过颜色深浅展示表现。

**优点：** 信息密度高，适合硬核用户。
**缺点：** 普通用户仍需理解颜色和归一化规则，同位置对比不够直接。
**结论：** 可作为以后增加的专家视图，不进入本阶段。

### 3.3 镜像条形图加单人雷达下钻

按照 1 至 5 号位将双方玩家对齐，当前维度使用统一刻度绘制镜像条形图；点击玩家后展示单人位置职责雷达和评分证据。

**优点：**

- 同位置对比清晰。
- 可容纳完整十人和未参与状态。
- 适合职责评分、原始数值和百分比。
- 能复用现有右侧审计面板与时间跳转。

**决定：** 使用本方案。

## 4. 页面结构

### 4.1 顶部

面板标题保持“十人贡献与责任审计”，右侧改为：

```text
[当前团战] [全场累计]
```

原有“前 7 分钟分路 + 资源推断”证据标签移动到图表副标题区域，并显示本次职责位置来源和置信度，不再占用主要操作位置。

### 4.2 维度选择

图表顶部使用单选分段控件：

```text
[职责评分] [伤害] [承伤] [控制] [治疗] [在场] [到场] [视野准备]
```

默认维度为“职责评分”。维度切换不改变玩家顺序，也不改变当前选中的玩家。

### 4.3 主图

主图按位置形成五行，每行同时显示天辉和夜魇：

```text
天辉玩家       数值  <- 条形图 | 位置 | 条形图 ->  数值       夜魇玩家
英雄 / 玩家                 1号位                 英雄 / 玩家
英雄 / 玩家                 2号位                 英雄 / 玩家
英雄 / 玩家                 3号位                 英雄 / 玩家
英雄 / 玩家                 4号位                 英雄 / 玩家
英雄 / 玩家                 5号位                 英雄 / 玩家
```

每侧显示：

- 英雄头像。
- 玩家名称。
- 位置标签。
- 当前维度原始值。
- 当前维度的条形。
- 数据状态图标。

条形使用相同量纲和同一最大值，不能分别按玩家缩放。

### 4.4 状态表现

| 状态 | 表现 | 是否显示职责分 |
| --- | --- | --- |
| `not_participant` | 头像与整行置灰，文案“未进入主战场” | 否 |
| `participant_no_events` | 浅灰条形，文案“在场但贡献事件不足” | 否 |
| `insufficient_evidence` | 灰色斜纹，文案“证据不足” | 否 |
| `blocked` | 黄色条形，文案“客观条件阻断” | 否 |
| `passed` | 使用正常团队色和评分等级 | 是 |
| `role_uncertain` | 位置旁显示低置信度提示 | 否 |

“证据不足”和“客观条件阻断”不能使用红色，也不能生成负面责任结论。

## 5. 图表维度与口径

### 5.1 职责评分

- 当前战斗：使用 `responsibilityScore`。
- 只有 `responsibility_gate.status == passed` 且 `role_confidence >= 65` 才显示分数。
- 全场累计：仅聚合通过门禁的战斗，使用战斗重要性与有效接触时长加权平均。
- 图表标签同时显示通过数量，例如 `76 · 8/12 场`。

### 5.2 伤害

- 当前战斗：`damage`。
- 次级标签：`teamDamageShare`。
- 全场累计：玩家有效战斗伤害总和。
- 全场队内占比：玩家伤害总和除以同队在同一批战斗中的总伤害，不能简单平均每场百分比。

### 5.3 承伤

- 当前战斗：`damageTaken`。
- 次级标签：`teamDamageTakenShare`。
- 全场累计规则与伤害相同。
- 承伤只是事实，不单独判断好坏；评价必须结合位置、死亡和控制价值。

### 5.4 控制

- 当前战斗：`controlSeconds`。
- 全场累计：有效战斗控制秒数总和。
- 雷达图使用位置模型给出的封顶得分，不直接把控制秒数跨位置比较为职责优劣。

### 5.5 治疗

- 当前战斗：`healing`。
- 全场累计：有效战斗治疗总和。
- 零治疗不能自动成为负面结论，必须满足英雄能力和职责门禁。

### 5.6 在场

- 当前战斗：`presencePct`。
- 全场累计：按每场有效接触持续时间加权。
- 远程或全图技能不能替代空间在场；沿用 `player-combat-timing/1.0` 的空间事实。

### 5.7 到场

- 当前战斗：空间到场相对队伍接触的延迟秒数。
- 优先使用 `combat_timing.fight_facts[].arrival_delta_seconds`。
- 旧分析包缺少该事实时，回退到 `arrivalDelay`，并标记为旧口径。
- 全场累计：使用中位数，同时展示 P75，避免单场长追击扭曲平均值。
- 该维度明确显示 `+Xs`，条形越长表示延迟越大。

### 5.8 视野准备

- 当前战斗：`setupObservers + setupSentries`。
- 支持下钻分别查看假眼、真眼和是否要求真眼检查。
- 全场累计：总和，并显示进入视野检查条件的战斗数量。
- 不要求真眼的战斗不能因 `setupSentries == 0` 扣分。

## 6. 完整十人数据构造

前端通过比赛英雄阵容构建固定十人名单，再将当前战斗的 `contributions` 按 `slot` 合并：

```js
roster[0..9] + contributionBySlot
```

当前战斗中没有 contribution 的玩家分为：

1. 不在 `fight.participants` 中：`not_participant`。
2. 在参与名单中但没有可归属事件：`participant_no_events`。

双方玩家按位置 1 至 5 排列。位置置信度低于 65 时仍保留玩家，但显示“位置待确认”，不进行确定职责评分。

## 7. 全场累计

“全场累计”以整场 Replay 的 `COMBAT_SEGMENTS` 为基础，不继承左侧列表“优先只看所选玩家参与战斗”的隐藏限制。它响应页面当前已有的战斗筛选器：

- 全部战斗。
- 重要及以上。
- 仅关键战斗。
- 仅团战。

标题下方显示实际聚合范围，例如：

```text
全场累计 · 团战 12 场 · 通过职责门禁 68/120 人次
```

聚合结果必须包含：

```json
{
  "slot": 0,
  "fight_count": 12,
  "participant_count": 10,
  "passed_gate_count": 8,
  "blocked_gate_count": 1,
  "insufficient_count": 1,
  "responsibility_score": 76,
  "damage": 24580,
  "team_damage_share": 18.4,
  "damage_taken": 19620,
  "team_damage_taken_share": 17.1,
  "control_seconds": 24.8,
  "healing": 3120,
  "presence_pct": 82.4,
  "arrival_median_seconds": 3.0,
  "arrival_p75_seconds": 6.0,
  "setup_observers": 2,
  "setup_sentries": 5
}
```

全场累计只改变图表数据范围，不改变左侧当前战斗选择，也不改变地图和事件流。图表副标题必须显示筛选范围和样本数，避免用户把“仅团战累计”误解为全部战斗累计。

## 8. 单人下钻

### 8.1 触发

点击以下任一位置选择玩家：

- 镜像条形。
- 英雄头像。
- 原始数值。
- 战斗地图英雄头像。

桌面宽屏复用右侧 `combat-inspector-panel`。窄屏自动切换到现有“个人责任”紧凑页签。

### 8.2 位置职责雷达图

雷达图只显示当前选择的一个玩家。每个轴使用 0 至 100 的位置内归一化得分。

1 号位：

- 输出占比。
- 减员转化。
- 技能执行。
- 在场输出。
- 生存代价。

2 号位：

- 输出占比。
- 技能执行。
- 控制价值。
- 到场时机。
- 在场率。

3 号位：

- 承伤价值。
- 先手或控制。
- 输出补充。
- 技能执行。
- 在场率。

4 号位：

- 技能执行。
- 控制价值。
- 治疗或功能。
- 视野准备。
- 在场率。

5 号位：

- 救人或治疗。
- 控制价值。
- 道具执行。
- 视野准备。
- 在场率。

英雄没有某类能力时，相应轴显示“职责不适用”，不以零分处理。

### 8.3 评分拆解

Parser 新增 `score_components`，避免前端复制隐藏公式：

```json
{
  "base": {
    "points": 24,
    "max_points": 24,
    "raw_value": 24,
    "status": "applicable"
  },
  "damage_share": {
    "points": 27.8,
    "max_points": 38,
    "raw_value": 27.8,
    "raw_unit": "percent",
    "status": "applicable"
  },
  "kill_conversion": {
    "points": 6.8,
    "max_points": 12,
    "raw_value": 48.8,
    "raw_unit": "percent",
    "status": "applicable"
  },
  "death_penalty": {
    "points": -14,
    "max_points": 0,
    "raw_value": 2,
    "raw_unit": "deaths",
    "status": "applicable"
  }
}
```

每个分项必须包含：

- 原始值。
- 得分或扣分。
- 分项上限。
- 是否适用于当前英雄和位置。
- 证据来源。
- 是否被职责门禁抑制。

前端不得重新实现 Parser 的职责评分公式。

### 8.4 维度详情

点击雷达轴、评分分项或主图当前指标后，显示：

- 实际值。
- 队内占比。
- 同位置对手值。
- 位置职责参考。
- 本项得分和上限。
- 数据置信度。
- 职责门禁状态。
- 关联事件列表。

“位置职责参考”是模型规则，不展示成职业比赛平均值，除非以后拥有可验证的基准样本。

### 8.5 关联事件

事件按钮沿用现有跳转协议：

- `fight_id`
- `time_ms`
- `player_slot`
- `event_kind`
- `event_seq`

点击后：

1. 更新战斗时间轴。
2. 同步小地图英雄位置。
3. 切换右侧“事件”页签。
4. 将对应事件滚动到可见区域并高亮。

## 9. Parser 输出变更

每条 contribution 增加：

```json
{
  "score_model": "position-responsibility/1.1",
  "score_components": {},
  "dimension_evidence": {
    "damage": [],
    "damage_taken": [],
    "control": [],
    "healing": [],
    "arrival": [],
    "vision_setup": []
  }
}
```

Parser 负责：

- 产生评分分项。
- 标记英雄能力是否适用。
- 标记门禁抑制。
- 提供可跳转的事实引用。
- 保证分项求和经过封顶后与 `responsibilityScore` 一致。

前端负责：

- 构造固定十人名单。
- 当前战斗与全场累计聚合。
- 图表渲染和交互。
- 数据状态和兼容提示。

## 10. 旧分析包兼容

旧分析包没有 `score_components` 时：

- 主图仍可展示现有原始指标。
- 通过门禁的职责总分仍可展示。
- 评分分解区域显示“旧分析包未包含评分分项，重新解析后可查看”。
- 不在前端猜测评分分项。
- 到场维度回退旧口径时明确标记。

不得因为旧分析包缺少新字段而使整个战斗页面空白。

## 11. 前端实现边界

### 11.1 纯数据函数

放入 `app-core.js` 并进行单元测试：

- `buildCombatContributionRoster`
- `aggregateCombatContributions`
- `combatContributionMetric`
- `combatContributionDisplayStatus`
- `combatContributionDrilldown`

### 11.2 图表运行时

扩展 `chart-runtime.js`：

- `BarChart`
- `RadarChart`
- `TooltipComponent`
- `GridComponent`
- `RadarComponent`

不引入第二套图表库。

### 11.3 页面状态

新增：

```js
combatContributionScope: "current"
combatContributionMetric: "responsibility"
combatContributionChart: null
combatResponsibilityRadar: null
selectedCombatContributionDimension: "responsibility"
```

切换战斗时：

- `current` 范围立即更新。
- 保留当前维度。
- 若当前玩家在新战斗中未参与，仍保留选择并显示缺席状态。

## 12. 响应式与可访问性

- 1280px 以上显示完整镜像图与右侧下钻。
- 960 至 1279px 保留镜像图，右侧下钻通过紧凑页签切换。
- 低于 960px 时改为天辉、夜魇两个纵向五人条形组，不压缩玩家名称。
- 所有图表数据提供等价的屏幕阅读器文本。
- 条形和状态不能只依赖颜色，必须同时使用文字、纹理或图标。
- 玩家行支持键盘聚焦和 Enter 选择。
- Tooltip 必须限制在图表容器内。

## 13. 测试策略

### 13.1 前端单元测试

至少覆盖：

1. 当前战斗补齐全部十人。
2. 未参与玩家状态为 `not_participant`。
3. 参与但无 contribution 时为 `participant_no_events`。
4. 门禁未通过时不显示职责评分。
5. 位置置信度低于 65 时不显示确定职责评分。
6. 全场伤害占比使用总量重算，不平均百分比。
7. 在场率按接触时长加权。
8. 到场延迟计算中位数和 P75。
9. 全场职责评分只使用门禁通过样本。
10. 当前战斗与全场累计切换不改变地图所选战斗。

### 13.2 Parser 测试

至少覆盖五个位置各一个职责模型：

- 分项求和与总分一致。
- 封顶规则一致。
- 死亡扣分为负值。
- 不适用能力不按零分处理。
- 门禁阻断时负面技能分项被抑制。
- `dimension_evidence` 可以定位到真实事件。

### 13.3 浏览器验收

使用至少三个真实 Replay：

- 10 人完整团战。
- 4 人小规模冲突。
- 含职责门禁不足和客观阻断的战斗。

桌面与窄屏分别验证：

- 当前团战默认选中。
- 十人全部出现。
- 未参与者置灰。
- 切换八个维度时图表不跳动。
- 点击左右任意玩家可打开对应下钻。
- 关联事件能跳到正确时间。
- 全场累计口径与原始数据一致。
- 没有文字溢出、图表裁切和 Tooltip 越界。

## 14. 验收标准

1. 页面首次进入时展示当前选中战斗的完整十人镜像图。
2. 同位置双方玩家在同一行，使用统一刻度。
3. 未参与、证据不足、条件阻断和确定评价四类状态可清楚区分。
4. 用户最多两次点击即可从总览进入某玩家某维度的原始事实。
5. 评分详情能够解释总分的每一项来源和扣分。
6. 所有负面责任判断均通过职责硬门禁。
7. 全场累计不会平均百分比、平均到场异常值或混入未通过门禁的职责分。
8. 旧分析包仍能查看原始指标，不出现空白面板。
9. 新增前端和 Parser 测试全部通过。
10. 真实 Replay 浏览器验收无控制台错误和明显布局溢出。

## 15. 非目标

本阶段不包含：

- 十名玩家同时叠加雷达图。
- 职业比赛或分段平均基准。
- 机器学习职责评分。
- 新增顶层导航 Tab。
- 用单个伤害或承伤数值直接判断玩家好坏。
- 修改战斗识别与分段算法本身。
