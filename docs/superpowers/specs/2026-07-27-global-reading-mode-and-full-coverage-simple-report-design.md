# Dota Lens 全局双层阅读与简明报告全覆盖设计

日期：2026-07-27

状态：已确认，待实施

## 1. 背景

当前单场页面存在两个产品问题：

1. `完整时间轴` 和 `数据覆盖` 作为独立页签占用导航空间，但普通用户几乎不会主动进入。
2. `比赛简报` 仍执行旧版内容裁剪规则，只显示三个阶段故事、一个优点、一个问题和一个训练目标。用户无法从中完整理解一整局做得好的地方和需要改进的地方。

本设计将阅读模式提升为全局偏好，并重新定义“简明”：

- 简明不是减少分析范围，而是完整分析、减少术语和默认收起次要信息。
- 专业模式与简明模式使用同一份 Replay 事实和同一套结论，不生成两份互相矛盾的报告。
- 技术审计不是第三种全局阅读模式，只在专业模式中按需打开。

本设计覆盖单场分析信息架构和前端表达层，不改变 Replay 作为事实源的原则。

## 2. 目标

### 2.1 产品目标

- 单场主导航从十个页签收敛为八个。
- 默认简明模式能够完整说明全场各阶段和六类职责表现。
- 所有可信优点和问题都能定位到时间、地点、地图或对应模块。
- 普通用户不需要理解协议、门禁和计分术语。
- 专业用户仍能查看完整指标、复杂表格和可重算技术审计。

### 2.2 成功标准

- 简明模式不再受“一个优点、一个问题”的数量限制。
- 六类分析均显示明确状态，不允许因为没有高优先级结论而出现空白。
- 每条明确结论都包含时间、位置、核心事实、影响和行动建议。
- 同一根因只展示一次主结论，重复发生点聚合在同一结论下。
- 简明模式不渲染内部技术字段。
- 阅读偏好在刷新和客户端重启后保持。

## 3. 非目标

- 本阶段不修改 Replay 解析协议和原始事件生产逻辑。
- 本阶段不重新设计战斗、打钱或视野算法。
- 本阶段不恢复人工标注功能。
- 本阶段不发布 GitHub Release。
- 本阶段不删除原始时间轴和覆盖率数据，只删除其独立产品入口并调整消费位置。

## 4. 信息架构

### 4.1 单场主导航

保留：

1. 发育复盘
2. 打钱分析
3. 地图轨迹
4. 视野分析
5. 出装技能
6. 战斗团战
7. 玩家评分
8. 玩家对比

移除：

- 完整时间轴
- 数据覆盖

`完整时间轴` 和 `数据覆盖` 不再作为可访问的独立页签，也不作为未知目标的回退页。

### 4.2 时间能力保留

以下能力继续保留：

- 页面底部全局播放时间轴。
- 发育、打钱、视野、战斗、出装和玩家报告内部时间轴。
- 结论的有界时间范围播放。
- 事件标记、拖动、缩放、前后事件切换。

移除的是独立事件列表页，不是时间定位能力。

### 4.3 数据可信度入口

顶部“数据来源”区域不再跳转独立页面。

简明模式：

- 默认只显示“本地 Replay”及可理解的状态。
- 只有数据缺口实际影响某项结论时，才在对应模块显示大白话说明。
- 不显示 Parser、Schema、原始缺失码和精度协议。

专业模式：

- 点击“数据来源”打开右侧“数据可信度”抽屉。
- 抽屉显示各模块可确认、受限和关闭的结论。
- 抽屉内提供“技术审计”二级入口。

技术审计：

- 显示原数据覆盖页中的 Parser、Schema、Patch 解析、记录数、精度、来源、状态和缺失码。
- 不默认展开。

## 5. 全局阅读偏好

### 5.1 模式

全局只有两种阅读模式：

- `simple`：界面文案显示为“简明”。
- `professional`：界面文案显示为“专业”。

默认模式为 `simple`。

### 5.2 入口

- 顶部工具栏常驻 `简明 / 专业` 分段控制。
- 设置页增加“阅读方式”设置，操作同一状态。
- 两处切换必须实时同步。

### 5.3 持久化

- 使用独立版本化 localStorage 键保存。
- 切换比赛、玩家和模块时保持当前模式。
- 刷新页面和重启客户端后恢复。
- 无效或旧值回退到简明模式。

### 5.4 DOM 边界

简明模式隐藏的技术字段不得仅通过 CSS 隐藏，必须不进入 DOM，防止搜索、辅助技术或复制文本泄露内部术语。

复杂表格和次要指标可以保留在 DOM 中，但必须使用明确的折叠组件并具备正确的 `aria-expanded` 状态。

## 6. 简明模式全覆盖报告

### 6.1 六类分析

玩家报告固定检查以下六类：

1. 对线
2. 发育路线
3. 地图节奏
4. 战斗
5. 目标与视野
6. 操作执行

每类必须输出一个状态：

- 做得好
- 基本正常
- 需要改进
- 证据不足

状态来自同一份维度、洞察和证据数据，不由前端根据胜负或单一聚合值猜测。

### 6.2 页面结构

简明报告按以下顺序展示：

1. 一句总评。
2. 一个最重要的下一局训练目标。
3. 六类表现总览。
4. 全场优点。
5. 全场需要改进。
6. 按时间排列的完整结论流。
7. 个人证据时间轴。

“三个关键时刻”可以继续作为顶部快速入口，但不再承担全场分析，也不限制下方结论数量。

### 6.3 结论选择

简明结论从完整 `rawInsights`、维度状态、故事节点和训练计划中生成，不使用 `brief.strengths`、`brief.priorities` 或旧摘要数组作为数量上限。

明确优点必须满足：

- 类型为正向行为或稳定优势。
- 通过普通模式资格门禁。
- 具备 L2 或 L3 定位。
- 具备时间范围和明确目标模块。
- 置信度达到现有正向结论门槛。

明确问题必须满足：

- 类型为改进、问题或优先事项。
- 通过职责和可归责门禁。
- 具备 L2 或 L3 定位。
- 具备时间范围和明确目标模块。
- 置信度达到现有负向结论门槛。

符合条件的结论全部展示，不设置固定数量上限。

### 6.4 去重和聚合

去重优先级：

1. 相同 `root_cause_id` 合并。
2. 相同实体和重叠时间范围合并。
3. 相同维度、相同事实和相同后果合并。

合并后：

- 保留一个主标题、根因说明、影响和建议。
- 所有独立发生点保存在同一结论下。
- 主列表显示首次或最关键发生点。
- 次要发生点折叠展示，可逐个跳转。
- 同一问题不会因为造成阵亡、装备延误、目标损失和视野缺口而重复批评。

### 6.5 单条结论

默认可见：

- 做得好或需要改进。
- 时间范围。
- 地图区域。
- 一条核心事实。
- 一条结果或影响。
- 一条行动建议。
- “查看这一波”按钮。

默认折叠：

- 次要指标。
- 对位比较。
- 同类发生点。
- 额外事实。
- 评分变化。

不允许只显示“注意节奏”“加强意识”等无法定位的泛化建议。

### 6.6 无结论和缺失数据

六类分析不能留空。

没有通过门槛的问题：

> 这局没有发现可以明确归责的问题。

没有通过门槛的优点：

> 这局还没有足够证据确认稳定优点。

数据不足：

> 这部分录像信息不足，暂时不判断对错。

不得使用低置信度聚合数据补写确定性结论。

## 7. 各模块的简明与专业层级

### 7.1 发育复盘

简明保留：

- 地图。
- 经济和经验主曲线。
- 阶段判断。
- 核心事实。
- 建议。

简明折叠：

- 全部检查点表。
- 次要对位指标。

专业完整展开所有检查点、差值和证据来源。

### 7.2 打钱分析

简明保留：

- 可缩放地图。
- 路线和资源时间轴。
- 漏线、低收益和危险路线结论。
- 每个问题的替代路线建议。

简明折叠：

- 逐单位收益。
- 完整候选路线比较。
- 威胁模型细项。

专业完整展开逐单位、营地、兵线和风险特征。

### 7.3 视野分析

简明保留：

- 可缩放地图。
- 眼位时间轴。
- 放置者、眼位类型、存活和发现事实。
- 眼位效果与建议。

简明折叠：

- 全部发现事件。
- 评分子项。
- 复杂视野覆盖指标。

专业完整展开生命周期和发现明细。

### 7.4 战斗团战

简明保留：

- 主战场地图。
- 战斗时间范围。
- 战斗结果和关键原因。
- 当前玩家职责表现和建议。

简明折叠：

- 十人复杂指标表。
- 责任计算明细。
- 技能和物品逐事件表。

专业完整展开十人图表、五维图、技能与职责证据。

### 7.5 出装技能

简明保留：

- 装备和技能时间轴。
- 关键装备完成时间。
- 明确延误和建议。

简明折叠：

- 完整伤害拆解。
- 逐目标技能矩阵。

专业完整展开所有装备、技能和伤害细项。

### 7.6 玩家对比

简明默认列：

- 英雄和玩家。
- K / D / A。
- 补刀 / 反补。
- 净值。
- GPM。
- 位置职责概况。

专业增加 XPM、伤害、承伤、治疗、视野、履职分和对位比较。

## 8. 专业模式和技术审计

专业模式默认展示：

- 所有图表和复杂表格。
- 十个评分维度。
- 维度分、角色权重和对位比较。
- 置信度与证据状态。
- 全部原始发生点。

技术审计按需展示：

- `player-report/*` 协议版本。
- Parser、Schema 和 Patch 解析信息。
- `gate_status`。
- `root_cause_id`。
- `embedded`、`modifier`、`context_only`。
- 基础分、行为修正和最终分。
- 抑制原因与原始缺失码。
- 可重算评分链。

技术审计关闭后回到原专业模式上下文，不改变当前玩家、模块、时间和滚动位置。

## 9. 术语规则

简明模式禁止出现：

- 协议名和版本号。
- Schema、Parser 和内部模型名。
- 门禁、计分路径、修正项、原子指标。
- 根因 ID、实体 ID、定位等级。
- 原始缺失码和字段名。
- “聚合事实”“程序推导”等无法直接帮助普通玩家的内部标签。

必要的数据不确定性使用：

- 证据充分。
- 证据有限。
- 信息不足，暂不判断。

专业模式可显示规范化中文术语。

技术审计可以显示内部字段原名。

## 10. 跳转重定向

删除完整时间轴页签后，实体跳转使用以下映射：

| 实体 | 目标模块 |
| --- | --- |
| 团战、阵亡、买活 | 战斗团战 |
| 目标、TP、地图移动 | 地图轨迹 |
| 购买、技能学习 | 出装技能 |
| 眼位 | 视野分析 |
| 对线检查点 | 发育复盘 |
| 资源路线、漏线、营地 | 打钱分析 |
| 未识别但有坐标和时间 | 地图轨迹 |
| 无坐标但有时间 | 当前来源模块的底部全局时间轴 |

所有跳转继续设置播放头和有界复盘范围。

## 11. 前端组件边界

新增或调整以下职责单元：

- `readingPreference`：读取、校验、持久化和广播全局阅读模式。
- `simpleReportModel`：从完整报告生成六类状态、去重结论和时间流。
- `simpleInsightPresenter`：只输出普通玩家可理解的结论字段。
- `professionalInsightPresenter`：输出完整专业字段。
- `technicalAuditDrawer`：承接原数据覆盖页和评分审计。
- `collapsibleDetails`：统一次要指标和复杂表格的展开行为。
- `reviewNavigationResolver`：不再回退到完整时间轴。

`simpleReportModel` 必须是纯函数，可在无 DOM 环境下单元测试。

## 12. 错误与降级

- localStorage 不可用时使用简明模式，不阻塞页面。
- 专业模块数据读取失败时保留已加载事实，并显示对应模块的大白话提示。
- 技术审计模块读取失败不影响简明报告。
- 旧分析包继续兼容，但缺少定位的旧结论不得进入明确优缺点清单。
- 删除页签后，旧书签或预览参数中的 `timeline`、`coverage` 回退到玩家评分或地图轨迹。

## 13. 测试设计

### 13.1 单元测试

- 无效阅读偏好回退到简明。
- 阅读偏好序列化和恢复。
- 六类状态全部生成。
- 所有符合条件的优缺点恰好出现一次。
- 相同根因正确合并。
- 多发生点保留且可逐个定位。
- 没有结论和数据不足时生成正确说明。
- 简明 presenter 不输出技术字段。
- 专业 presenter 保留完整字段。
- 删除时间轴页后的实体映射正确。

### 13.2 DOM 测试

- 主导航不存在“完整时间轴”和“数据覆盖”。
- 不存在可激活的 `detail-timeline`、`detail-coverage` 页面。
- 简明模式仍存在地图、时间轴、核心事实和建议。
- 复杂表格默认折叠且 `aria-expanded=false`。
- 专业模式完整展开。
- 技术审计只在专业模式可打开。
- 两个阅读模式入口同步。

### 13.3 真实 Replay 回归

使用 `8894766243` 验证：

- 十人报告均能生成六类状态。
- 可信优点和问题没有被旧摘要数量截断。
- 同根因不重复。
- 每条明确结论可以跳到正确模块和时间。
- 简明与专业结论不矛盾。
- 技术字段不会出现在简明页面文本中。

### 13.4 视口验收

- `1024×720`
- `1460×920`
- `1920×1080`

检查：

- 顶部模式切换不挤压标题和操作按钮。
- 八个单场页签可完整使用。
- 折叠内容不导致横向溢出。
- 地图和时间轴仍具有可操作尺寸。
- 文字没有裁切或遮挡。

3. 删除两个独立页签与对应页面入口。
4. 重定向全部内部跳转。
5. 增加全局模式切换和设置项。
6. 改造玩家评分简明页面为六类全覆盖。
7. 对各单场模块增加简明折叠和专业展开。
8. 将数据覆盖迁移到专业模式技术审计抽屉。
9. 运行前端测试、构建、真实 Replay 回归和三档视口验收。

## 15. 兼容性与文档优先级

本设计更新并取代以下旧要求：

- 简明模式严格限制一个优点和一个问题。
- 三个关键时刻代表完整比赛分析。
- 数据覆盖必须作为独立单场页签。
- 完整时间轴必须作为独立单场页签。

保留的旧原则：

- 明确结论必须有事实和定位。
- 同一根因不能重复扣分或重复批评。
- 缺失数据不按零分处理。
- 简明和专业使用同一事实源。
- 普通模式不显示内部技术术语。
